This repository contains the implementation and analysis artifacts for the paper *Understanding Efficient LLM Serving: An Empirical Study of Frameworks, Optimizations Algorithms, and Real-World Adoption*. It investigates how open-source GitHub projects adopt vLLM, SGLang, TensorRT-LLM, LMDeploy, and FlashInfer. For **RQ1—framework popularity, adoption, and efficient serving methods**—[`most_adopted_serving_frameworks.ipynb`](code/most_adopted_serving_frameworks.ipynb) analyzes framework adoption, while [`cost_efficient_method.ipynb`](code/cost_efficient_method.ipynb) examines serving-method usage. The `B - step 1` through `B - step 3` notebooks prepare this analysis by extracting framework calls, filtering repositories, and identifying imports and parameters. For **RQ2—combinations of serving methods and frameworks, and framework adoption across LLM types**—[`B - step 4_updated - find combinations of import params usage.ipynb`](code/B%20-%20step%204_updated%20-%20find%20combinations%20of%20import%20params%20usage.ipynb) analyzes method co-usage, [`combination_of_serving_frameworks.ipynb`](code/combination_of_serving_frameworks.ipynb) examines framework combinations, and [`llm_models.ipynb`](code/llm_models.ipynb) extracts and categorizes model usage.

For **RQ3—how serving frameworks are used across different types of LLM-based software systems**—the `A` notebooks implement the repository-characterization pipeline: [`A - step 1`](code/A%20-%20step%201%20-%20filter%20repos%20and%20prepare%20repo%20descriptions.ipynb) filters repositories and prepares descriptions; [`A - step 2`](code/A%20-%20step%202%20-%20repo_summary.ipynb) generates structured summaries of repository intent, technical focus, primary use case, and system design; [`A - step 3`](code/A%20-%20step%203%20-%20topic%20modeling%20-%20first%20step%20-%20running%20the%20topic%20modeling%20.ipynb) performs topic modeling; and [`A - step 4`](code/A%20-%20step%204%20-%20topic%20modeling%20-%20result%20analysis.ipynb) analyzes the resulting topics and repository assignments. Shared extraction, preprocessing, model-classification, and topic-modeling functions are implemented in [`code/utils.py`](code/utils.py), while [`paper_plots.ipynb`](code/paper_plots.ipynb) contains figure-generation code. The `dataset/` and `code/topic_modeling_results/` directories contain collected data, intermediate results, and analysis artifacts; large published CSV files are managed with Git LFS, and archived processing results are excluded from Git tracking.
